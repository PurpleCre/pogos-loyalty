# Pogo’s screen-by-screen UI review

4 November 2026. The user selected **teal, charcoal and white**, based on the existing Pogo’s logo. This is an application UI increment, not release approval.

## Shared design and interaction changes

- One colour source in `config/theme.json`, shared by NativeWind and typed screen styles. Dark teal carries primary actions; charcoal carries headings; white cards sit on a pale canvas. Red remains for errors, deletion and refunds; amber remains for uncertainty and operational warnings.
- Safe-area-aware screen headers, consistent back navigation, bounded desktop content, scrollable forms and clear section headings. The drawer uses the actual logo and preserves its role-dependent destinations.
- Shared buttons and inputs use larger targets; small native touch controls have a 44px minimum. Forms retain labels, keyboard settings, disabled states, pending-action protection and accessibility roles. Native status-bar content is dark against the light header.
- Empty, loading and stale-data treatments stay explicit. Cached information is not presented as current. Login, profile saving and meal-option validation now have inline feedback in addition to native alerts.

## Browser crash corrected

Visual testing reproduced `codegenNativeComponent is not a function` after entering branch selection. The native map marker was being evaluated in the browser’s shared route bundle. `components/LocationMap.tsx` now owns the native import; Metro selects `LocationMap.web.tsx` in browsers.

Android/iOS retain the existing interactive map. The browser fallback explicitly offers current-location permission or a labelled latitude/longitude pin, with coordinate-range validation and a required written address in the existing delivery flow. It does not pretend to show an interactive map, invent an address, add a map provider or change server-side delivery coverage validation.
